  - The *Trộn* box holds the view bar (*Bề mặt*, *Concept*/*Bản trộn*, *Mã trộn*, *Sao chép*, *Mở màn riêng*) and the matrix. It sticks to the top while the page scrolls, on windows at least 1000px wide and 640px tall.
  - Once stuck, the box condenses to one line, about 45px. Why: on a laptop screen, the 160px box still hid the bottom of the preview.
    - Four small chips show the current mix (screen, colour, type, button), with *Đổi trộn*. *Đổi trộn* drops the matrix over the preview. Picking a cell keeps it open. A click outside, Esc, or scrolling back to the top closes it.
    - A margin makes up for the height the box gives back, so the preview does not jump when the box condenses.
    - A scroll that stops while that margin still shows finishes on its own, in the direction it was going (`scrollend`, one event per finished scroll, not a scroll listener).
      - Going down, the page settles where the preview meets the bottom of the condensed box, with the preview's header in view. Going up, it settles where the box is full again.
      - Why: a wheel notch moves about 100px, so the page rarely stopped at that point. Condensing as soon as the box stuck left an empty band about 110px high. Condensing later hid the preview's header under the box.

    - An `IntersectionObserver` on a mark near the top of the board decides when to condense. Preflight P04 forbids scroll listeners.
    - The page turns off scroll anchoring (`html{overflow-anchor:none}`). Why: on the real board, Chromium picked an anchor inside a sticky area and pulled the page back to the top every time the box condensed. The box then opened and condensed in a loop, which looked like a jerk.
    - The margin goes up before the box condenses. Why: measuring the condensed box briefly made the page shorter, and on a short page the browser pulled the scroll position up.
    - A click on the preview also closes the dropped matrix and the brief. The click lands inside the iframe, so the board only sees its window lose focus to that iframe.
  - The full box is lower: about 160px for 12 concepts, down from about 220px.
    - The letter row on top repeated the *Màn và ý* row, so it is gone. A concept that borrows a screen shows its letter, muted, next to that screen's letter (`D màn B`).

    - The concept count, *Brief concept*, *Nền* and *Khổ màn* move to the top of the left column, above the concept list. The column sticks with the box, and only the list scrolls. Opened on its own, the board keeps its title row with the project name.

- The QA kit's `run.mjs` no longer slows the machine down or fills the temp folder. Why: on a laptop, the test suite opened many headless browsers at once and the machine lagged. The temp folder also held 633 leftover `cdp-*` profiles from over a week (about 12 MB each), left by runs stopped midway.
  - It runs at below-normal priority, and lowers every browser process once a second. Why: the browser raises its page processes back to normal and its GPU process to above normal (measured with Edge). `QA_PRIORITY=normal` keeps normal priority.
  - The browser starts without the work a fresh profile does on first launch: built-in extensions, component updates, background networking, translation, sync. Why: below-normal priority still lets the suite take every idle core, so the CPU stayed at 100%. Measured with Edge on a two-step page: 11.8 core-seconds of CPU per run, down to 5.2, and 8 page processes, down to 2. A run takes the same time.
  - `QA_BROWSERS=n` limits the headless browsers open at once on the machine, across all commands. A command over the limit waits for a free slot.
  - One command, one browser. Why: with the lean flags, one `run.mjs` run still cost about 5.2 core-seconds, and starting the browser plus creating and deleting its 12 MB profile was more than half of it (measured: start 1.6, page load 0.8, the steps 0.4, node 0.3, the rest in the profile). The test suite started a browser hundreds of times; `handover.py run` started one per suite per theme.
    - New `_qa/launch.mjs` holds the browser start and stop that `run.mjs` had. New `_qa/browser.mjs` starts one browser for a command, prints its URL, and closes it when its stdin closes, so a killed command leaves no browser behind. `qa_init.py` copies both; a kit with either file changed reruns every suite.
    - `run.mjs` with `QA_CDP=http://127.0.0.1:<port>` attaches to that browser in a browser context of its own (empty `localStorage`, cookies and cache, as with a fresh profile) and a window of its own, and disposes them at the end, also after an error. Its command line, output and exit codes are unchanged, so a kit installed before this still runs.
    - `run_all.py`, `quick.py`, `handover.py`, `breaktest.py` (through `run_all.shared_browser()`), `qa-check.py`, `shots.mjs`, `system-check.mjs`, `map.mjs --shots` and the test files that run `run.mjs` open one browser each. A command that cannot (old kit without `browser.mjs`, no browser found) runs as before. A command started under another one reuses its browser.
    - Tests: `browser.mjs` prints the URL and closes on stdin; two attached runs do not see each other's `localStorage` and leave no `cdp-*` folder; two attached runs at 1440 and 390 in parallel each measure their own width; an attached run that fails leaves the shared browser alive; a `QA_CDP` with no browser exits 2; `qalib.shared_browser()` sets and clears `QA_CDP`, stops the browser, reuses a parent's, and enters and leaves quietly when `browser.mjs` is missing.
  - The profile is deleted after an error or Ctrl+C too. A run killed outright cannot do that, so each run deletes up to 20 `cdp-*` profiles that have not changed for 2 hours.
  - Tests: a run that fails midway leaves no profile, old profiles are swept, and with `QA_BROWSERS=1` two parallel runs open their browsers one after the other.
- Tests: the box condenses and the preview does not jump, a scroll that stops mid-way settles with the preview right under the box, going down or up, the page is not pulled back when the box condenses, *Đổi trộn* opens and closes the matrix (a click on the preview closes it), *Sao chép* falls back when the clipboard is blocked, the box sticks after scrolling, the overview shows each concept's shot newest round first without doubling the left column's cards, names a missing shot, follows *Khổ màn*, and closes on a pick, Esc or a click outside, the recommended concept is marked, the board drops its title row with `?hub`, the hub follows the board's *Nền* and ignores other messages, the brief does not push the board down, the caption sits in the bar on one line and drops the whole sentence on a click, the screenshot shows on hover and on focus, and the box does not stick at 390.

## 1.6.0 (2026-10-06)

- Skills: new `sketch-to-map` 1.0; `sketch-to-site` 4.6, `sketch-to-concept` 1.5, `evolve-site` 1.10, `tweak-site` 1.4, `handover-check` 1.4.
- New skill `sketch-to-map`, run between the concept and the build of a large project (from two requirement docs, 15 features, two roles or several surfaces). Why, from measurements:
  - On a mock BA document set (`r7-map`: 7 docs, 48 KB, 43 features), the current flow read everything in one turn and missed 1 feature, a state change found only in `schema.dbml`. Its scope proposal built 10 of 26 screens and nothing tracked the other 16 after gate 3.
  - A real 28-page prototype built with `sketch-to-site` 4.x covered every use case, but had 17 shortcuts that sent the user to another page with no way back, one page carrying 10 use cases with 21 primary buttons, a daily task with no menu entry, a menu group named after a release phase, and eight roles sharing one menu. Its per-page UX review scored 57.8/60 and a tree test run by models scored 100 %: both miss faults that only show across a flow.
  - `scripts/sources.py` turns the docs (`.md`, `.txt`, `.html`, `.docx`, `.xlsx`; `.pdf` with `pdftotext` or `pypdf`) into text with fixed line numbers in `map/_src/`, and writes their table of contents, the code systems it finds, Must items, dropped use cases, and the enums and state changes of `schema.dbml`. It proposes reading everything in one turn up to about 300 KB, or one worker per module beyond. A real 1 MB BA set took 0.35 s. A prefix with 50 or more codes found almost only in table rows (the student IDs of a data appendix exported from Excel) is recorded as data, not as a code system: otherwise `ids.json` grew from 11 to 89 KB on a mock with such an appendix, and the P24 scan would have flagged every student ID shown on a page as a leaked reference code.
  - `map/features.js` lists one feature per line: a verb and object in the user's words, source codes or line ranges, roles, frequency, stated or inferred (inferred ones are confirmed at the gate), in scope or deferred. `references/m1-kiem-ke.md` lists where features hide (rules, the permission matrix, edge cases, automatic jobs with settings, reports, bulk actions, appendices, decisions that override older text) and adds a separate pass for state changes and nested exceptions, the only places the measurements found misses.
  - `map/layout.js` holds surfaces, roles with a home page each, modules with one-way `depends` and a build batch, screens with zones, tabs and home-page bands, a menu per role, a place for every feature (screen, zone or tab, tier 1–4, how it opens), shortcuts, journeys and 5–10 daily tasks. `references/m2-bo-cuc.md` gives the layout rules with the law behind each threshold (Hick, Miller, Jakob, Nielsen #3, #4, #6, WCAG 3.2.4, KLM…).
  - `scripts/map.mjs check` blocks a use case, Must item, state change or doc section that no feature covers; a shortcut that opens another page without a declared way back; a home-page item that is neither on the home page nor a shortcut from it; a role without a task-based home page; a menu group named after a release; a reference code in a label; a tier-1 task more than 3 steps from the role's home (with a KLM time estimate); a journey step or daily task the role cannot reach. It warns on screens with more than 6 features or 5 tabs, more than one tier-1 task on a screen, menu groups over 7 items, and one task under two labels. It writes `MAP.md`, copies the click-through frame to `map/index.html` and, with `--shots`, shoots each role's home page. `visible --treetest` writes a label check for one read-only tester, `slice` prints one screen for the build, `coverage` checks the built pages, and `merge` joins the parts written by workers.
  - `templates/map-shell.html` is a grey click-through frame: role switch, real menus, home pages, zones and tabs, `…` menus, Ctrl+K, shortcuts that open as declared (dialog, drawer, sheet; a page shortcut has Back and returns on Done), placeholder pages for deferred screens, a feature index, and a *Bấm thử* list of daily tasks where the user marks each one easy, OK or hard and copies the result back. Tested in Edge at 1440 and 390 at the size of a 150-feature, 11-role project.
  - Measured on `r7-map`, two runs: 43/43 features and 18/18 traps in both, against 42/43 and 17/18 for the current flow, including the state change found only in the schema; no feature built that should not be. Every blocking layout metric was met on the first check after `layout.js` was written: no shortcut that leaves the page, a home page for every role, densest screen 6 features with 3 tabs against about 10 with 4, the 4 deferred features placed in the map. Cost: 18–19 turns and about 0.62M converted tokens without one subagent cache miss, above the target of 15 turns and 0.5M. The extra turns were then fixed: the M0 command sits in the entry table; files are written and checked in the same turn; the map gate's `DECISIONS.md` block is printed in SKILL.md; a clean `check --shots` prints a *Trình ở cổng* block (inferred features, notes with conflicts and open questions, modules in build order with their Must count), so `MAP.md` need not be read; the blocking list prints up to 40 lines; `m1-kiem-ke.md` says the M0 output is enough and shows `suy`, `notes` and `hoan` in its example. Re-measured with two more runs: 10–11 turns and 0.42–0.48M without cache misses, both targets met, quality unchanged (43/43, 18/18, the schema-only state change caught, 0 blocking items on the first layout check).
  - Data appendices do not count towards the 300 KB limit: `sources.py` marks a doc `data` when 200 or more of its lines, and half of them, carry a data code (student IDs of an Excel export); such a doc is not read, needs no `skip`, and `check` ignores its sections. Two re-runs on the mock below ignored the "split" advice on their own, read the 48 KB of real requirements whole and skipped the appendix: 0.52M and 43/43, against 1.31–1.47M with workers.
  - `features.js` and `layout.js` are written with the `Write` tool, never with a Bash heredoc: one measured run (`rml6`) wrote `features.js` by heredoc, listed the folder, then wrote it again with `Write`, two extra turns (about 110k).
  - Worker path, for docs over 300 KB, measured on a mock that adds a 328 KB data appendix (two runs): the split was chosen, the appendix codes were read as data, each worker read only its own line ranges, the main agent never read the appendix, and coverage held at 43/43 and 18/18. Total cost 1.31–1.47M with the workers. Changes from what the runs showed, not re-measured yet: at most 4 workers, called in one wave (7 workers ran in two waves of about 5 minutes); the worker prompt template reads the rules and its ranges in one turn, with the rule sections' exact line ranges kept in step by a test, and counts its return line without scripts (a run whose prompt lacked this took 6–11 turns per worker instead of 4, 0.16M more); the main agent writes `map/parts/_chung.js` with `skip` for shared sections such as summaries, tables of contents and data tables (otherwise the first check blocked on 20–21 of them) and gives each shared use case to one module; `merge` prints suspected duplicate pairs across parts and says to Read `features.js` before editing it (an edit was refused, and a heredoc script broke); `check` also warns when one name is the start of another and both share a role (5 of the 6 worker duplicates of one run; no false hit on 8 measured inventories); the gate block prints every conflict first and in full, and conflicts are noted with a short quote of each side (with 43 notes cut at 20, both runs searched `features.js` for them).

  - One gate, *Cổng Bản đồ*, unnumbered, so projects in progress keep gates 1–4. The stop rule and excuses table are shared with `sketch-to-site` and `sketch-to-concept`: the `luat-dung:co` block is now tested in three files. A second table lists the layout excuses behind the measured faults.
